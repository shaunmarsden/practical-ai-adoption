## Demonstrated findings

### A1 - Narrow viewport with enlarged text causes horizontal text overflow (low severity)

Reproduce: open workbench at 320 CSS pixels wide; enlarge root text to 200% (runner uses document.documentElement.style.fontSize='200%'). The heading 'Workbench' exceeds its content box: H1 clientWidth243 / scrollWidth337; the document scrollWidth becomes376 at viewport320. Several labels also overflow their boxes. Screenshot: overflow-h1.png. Browser result reproduced in Chromium, Firefox and WebKit. This combines a small viewport with text enlargement; normal 320px reflow and 200% text at390px both passed. It is a demonstrated stress-case issue, not a claim of a formal WCAG failure under actual browser zoom.

Smallest proposed fix: main { overflow-wrap: anywhere; }. A browser-only CSS probe reduced document scrollWidth to320 in Chromium and Firefox. No production edit made. Check resulting word breaks visually before adopting.

### A2 - Native file button wording clips at 320px with enlarged text (low severity)

Same setup. The native file input is175px wide internally; Chromium 'Choose File' is visibly clipped to 'Choose Fi...' and Firefox native button is also clipped. Screenshot: chromium-200-file-input.png. The external 'Reopen draft' label and full help remain present, so no complete loss of the action or accessible name is demonstrated. Native filename is reset immediately by the app; the long-filename invalid-upload challenge therefore tests status/error handling, not a persistent filename display.

Smallest proposed fix: input[type=file]::file-selector-button { max-width:100%; white-space:normal; overflow-wrap:anywhere; }. Browser-only probe showed full two-line 'Choose File' in Chromium and full wrapped Firefox button wording (screenshots chromium-fix-probe.png / firefox-fix-probe.png). The native no-file-selected area still clips, so this is a partial layout improvement, not a complete custom file-control solution. Keep native input semantics and external label. No production edit made.
