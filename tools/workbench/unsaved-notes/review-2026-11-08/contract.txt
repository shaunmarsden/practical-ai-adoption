Unsaved-note protection: pre-implementation contract, 8 November 2026
Baseline: 0ff54ba4f291fc1036443cffceedda6bf927e4f5
No feature implementation exists when this contract is issued.

Value: reduce accidental loss of newer edits without autosave, storage, extra assessment logic or a claim that a downloaded file was kept.

1. Initial empty/default notes are unchanged; ordinary navigation/reload has no leave warning.
2. Editing any note (textarea/select/date) away from the checkpoint marks changes. Checkpoints are: initial defaults; last successfully reopened JSON notes; notes captured in a JSON download REQUEST that completes without a synchronous error; confirmed clear -> defaults.
3. Reverting ordinary notes to their checkpoint values clears changes. Preserve imported CRLF/CR strings while untouched or unrelated fields change. If an edited field returns to the checkpoint's original displayed value, restore its original exact checkpoint string as well, avoiding hidden line-ending loss.
4. JSON Save captures the exact notes placed in that file. A synchronous download failure must not move the checkpoint. Download success wording must still say requested and cannot claim the file was retained. Any edits newer than the captured JSON remain changed. Text export/preview/navigation do not reset the JSON checkpoint.
5. Invalid/read-failed/oversized imports, cancelled picker, cancelled replacement, cancelled clear and pending reads do not silently reset tracking. Successful reopen and confirmed clear establish new checkpoints. Existing atomic import/race protection and data preservation must remain intact.
6. Native beforeunload protection is attached only while changed, removed when unchanged, and uses standard browser confirmation rather than custom safety/approval text. Cancelled leave/reload keeps notes, selections and preview intact. Accepting leave/reload may discard notes; no automatic recovery is promised. New-tab guide/V2/feedback links and within-page steps should not warn or lose notes.
7. Check current form values on input and change, and reconcile restored controls on pageshow. Do not promise reliable warning for mobile process termination, tab closing without an event, browser crash or browsers without native dialog support/sticky activation. Do not use persistence to compensate.
8. Visible status (#changes-status, role=status) describes changes relative to the checkpoint. Do not announce every keystroke when state is unchanged. No green approved/safe/saved guarantee. Saving/reopening still does not verify evidence, run V2 or grant authority.
9. No localStorage, sessionStorage, IndexedDB, cookies, service worker, remote writes, telemetry or automatic downloads. Browser memory and bfcache can retain state naturally; do not claim erasure on every history navigation. The JSON schema and 28 note fields stay unchanged.
10. Source/API contract for independent state tests: changes.mjs exports createChangeTracker(initialNotes), returning capture(notes, kind), hasChanges(notes), checkpointValue(id), checkpointKind(); values/snapshots must be copied, not aliased. kind is initial, reopen, download or clear. Implementation details beyond this can vary. Browser UI keeps existing selectors, with only #changes-status added as a stable status region.

Review protocol: fresh contexts read only this contract plus frozen baseline AGENTS/workbench files, not older tests or review keys. Freeze bounded fictional challenge facts/expectations and hashes BEFORE implementation. Send only readiness and manifest hashes; withhold concrete case contents until an implementation checkpoint commit. Preserve first results and failures, disclose harness adapters, never pass expected outcomes/case IDs into app logic, and distinguish software/browser evidence from human or real-device validation.
